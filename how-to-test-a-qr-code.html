How To Test A QR Code Before You Print It

Use this repeatable test process to check a QR code's destination, scan reliability and real-world print performance before customers see it.

Test the final QR code, not just the draft

A QR code can look correct on screen and still fail on a poster, menu or product label. Exporting, resizing, adding a logo, changing colours and placing it on a textured surface can all affect scanning. Test the exact file you intend to publish, and test it again after it has been printed or installed.

Start by scanning the code with your normal phone camera. The scan should open the intended page promptly, without a confusing warning, login requirement or broken redirect. Then repeat the test on another device. A second phone helps reveal cached pages, browser-specific problems and scan issues caused by one camera app.

A six-step QR code test

  1. Check the destination. Scan the code and compare the address that opens with the destination you intended. Check every link, form, download and booking action on that mobile page.
  2. Use more than one phone. Try at least one iPhone and one Android phone when possible. Use the native camera first, then a common QR scanner if the campaign is important.
  3. Test at normal distance. Stand where a real visitor will stand. A table-tent code is tested at arm's length; a window poster or sign should be tested from several metres away.
  4. Test the printed version. Print at final size on the intended stock. Gloss, folds, curved packaging, low ink levels and dark backgrounds can all change the result.
  5. Try ordinary conditions. Test in indoor light and, where relevant, in shade and daylight. Reflections on laminated menus and shop windows are a common source of failed scans.
  6. Check the next action. The landing page should load quickly, be readable on a phone and make the promised action obvious. A successful scan that leads to a poor page still wastes the opportunity.

What to check on the printed piece

Keep a clear empty border around the code. This is called the quiet zone, and it should not contain copy, decoration or a border that crowds the QR pattern. Use a dark code on a light, plain background unless you have tested a different treatment thoroughly.

Do not stretch or squash the code. It must remain square. Avoid saving a small QR image and enlarging it until its edges look soft. Export a sufficiently large PNG or, for print artwork, use an appropriate vector format when your generator provides one.

Place a short instruction beside the code that explains the value of scanning, such as “View the full menu”, “Leave a review” or “Get directions”. This gives people a reason to scan and lets them notice quickly if they opened the wrong destination.

When a QR code will not scan

First, scan the original exported file. If it works on screen but not in print, inspect the size, contrast, quiet zone and material. If it fails both on screen and in print, generate a fresh code from the exact destination URL and compare the results.

A dense QR code needs more space to scan reliably. Long URLs, contact records and large blocks of text create denser patterns. Use the shortest practical destination URL, especially for small printed items. Adding a logo or using very high error correction can also make a code denser, so test those design choices at final size.

Pre-publication checklist

  • The code opens the correct secure destination on two phones.
  • The landing page works without a login or desktop-only interaction.
  • The code scans at the actual viewing distance and in typical lighting.
  • The final printed or installed version has been scanned successfully.
  • The code is square, sharp and surrounded by a clear quiet zone.
  • The nearby call to action matches the page that opens.

How often to retest a QR code

Retest every time you change the QR artwork, its landing page or its placement. For a permanent printed code, add a recurring check to your site-maintenance routine. Static QR codes do not expire by themselves, but their destination can move, be removed or become unsuitable for mobile visitors.
